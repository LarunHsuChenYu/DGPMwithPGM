# AGENT_ANALYSIS.md — 需求與高風險變更分析手冊

> 本文件適用於 SA 模式，以及依 [`AGENT_CONSTITUTION.md`](AGENT_CONSTITUTION.md) §7 判定為**高風險**的變更。  
> 僅能補充 `AGENT_CONSTITUTION.md`，不得降低其優先順序或安全、資料完整性要求。

## 1. 何時使用

符合任一情形時，必須使用本手冊：

- 需求存在歧義，無法由已核准 SRS／BMW 或既有 `domain/*.md` 可靠判定。
- 變更涉及資料表、索引、預存程序簽名、資料轉換或歷史資料。
- 變更涉及公開 API／JWT Contract、Auth 流程或密碼演算法。
- 變更涉及權限鏈（`MAP_ROLE_FUNCTION`→`SET_FUNCTION`）、角色定義或授權真相。
- 變更需要停機、部署排序、Feature Flag、回復或資料修復計畫。
- 未來若新增對外 Consumer（例如 DGPM 改接本平台 API），其契約變更。

## 2. 分析前蒐集

分析前應確認下列事實；未知項目必須列入 Open Questions，**不得自行補假設為既定規則**。

- 需求來源、核准狀態、預期使用者與驗收標準（對照 `docs/PGM_Qlik_*.docx`、BMW）。
- 涉及的領域（`domain/*.md`）、資料表、API、Web 頁面與外部 Consumer（若有）。
- 資料主責系統（本階段預設＝PGM）、寫入者、同步方向、觸發時機與失敗補償方式。
- 現有權限：角色×功能、`DEL_FLG`、稽核欄、個資（EMAIL／TELEPHONE）與密碼處理。
- 資料量、可接受停機時間、RTO／RPO（若有）；開發／測試環境是否可先驗證。

## 3. 必要分析項目

### 3.1 業務與狀態規則

- 列出登入、改密、角色切換、帳號啟停、角色權限覆寫、參數 CRUD 等動作的前置與禁止條件。
- 對每個狀態轉移定義觸發者、授權、交易邊界、不可逆性與例外處理。
- 明確判定主責；禁止由非主責系統覆寫主責欄位（本階段主責＝PGM）。

### 3.2 資料庫與資料品質

- 確認 Schema、索引、View、Repository SQL 與 Seed 的相依性；表範圍以 BMW LIST 為準。
- 評估鎖定、死結、交易長度、併發更新、重送與冪等性（例如角色權限「全量刪後插」）。
- 說明資料轉換範圍、筆數估算、備份點、驗證 SQL 與資料修復方式。
- 禁止以 `NOLOCK` 掩蓋 Blocking 或 Deadlock。
- 禁止將外部 HTTP／檔案傳輸包在長時間資料庫交易內。
- 本專案無 RowVersion；併發控制依既有 `DEL_FLG`＋稽核欄，若需樂觀鎖須另案停等。

### 3.3 安全與授權

- 列出功能權限（`MAP_ROLE_FUNCTION`×`SET_FUNCTION`）與物件層級範圍（若日後有廠區／組織）。
- 不可僅依 UI、Route、前端傳入的使用者或角色識別判定授權。
- 密碼僅 BCrypt；確認日誌、匯出檔、錯誤訊息與 Payload 不洩漏密碼／Token／連線字串。
- JWT SecretKey 與連線字串不得進入原始碼。

### 3.4 整合與契約

- 定義來源、目標、主從關係、契約版本、必要欄位與相容性期間。
- 確認 Timeout、重試、冪等鍵、失敗補償及對帳責任（若有 Consumer）。
- 公開 API／JWT Claim 的破壞性異動，必須提出相容方案或 Consumer 遷移計畫。
- 本階段：與 QMS 不共用 `EMP_USER`（未另定案前）；無 ERP／SCM／MES／EDI 拋轉。

### 3.5 部署與回復

- 定義部署順序：資料庫（`SQL/`）→ Api → Web → 設定／IIS。
- 說明是否需要 Feature Flag、雙寫、回填、相容期間或停機窗口。
- 定義回復觸發條件、程式回復、資料回復、資料修復及決策責任人。
