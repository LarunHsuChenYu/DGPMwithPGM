# DGPM_SPM 安裝文件

## 專案簡介

`DGPM_SPM` 是以 .NET 10 與 Clean Architecture 建立的平台基礎服務，內建 Dapper 資料存取、JWT 認證（外連 PGM）、**NLog** 與測試守護。業務涵蓋基本資料（區域／經銷商）、系統參數（匯率）、KPI（指標／匯入／覆核／異動／資料權限）等 REST API，以及 Blazor 前端 `DGPM_SPM.Web`。帳號／角色／功能選單／登入歷程主責為 **PGM**。

> **Log 路徑**：NLog 寫入部署資料夾旁邊的 `C:\inetpub\logs\`（與 `DGPM_SPM`、`PGM` 同層；非站台目錄內）。應用程式檔名見「部署到 IIS」步驟；`C:\inetpub\logs\LogFiles` 為 IIS 系統存取紀錄，勿混淆。

方案包含下列專案：

- `DGPM_SPM.Api`：HTTP 入口、Controller、Middleware、JWT、Swagger 與 DI 組裝。
- `DGPM_SPM.Core`：Domain Entity、Application Service、介面、DTO 與業務規則。
- `DGPM_SPM.Infrastructure`：Dapper、SQL Server、Repository、DbSession 與 Unit of Work 實作。
- `DGPM_SPM.Web`：Blazor Server UI；經 HTTP 呼叫 Api（`SpmApi:BaseUrl`），無對 Core／Infrastructure 的 ProjectReference。
- `DGPM_SPM.Core.Tests`：Core 單元測試（xUnit + Shouldly + NSubstitute）。
- `DGPM_SPM.Api.Tests`：Api Controller 單元測試（直接 new Controller + mock Service）。
- `DGPM_SPM.Architecture.Tests`：分層及 Entity 命名守護測試（NetArchTest）。
- `DGPM_SPM.Web.Tests`：Blazor 元件／導覽 helper 測試（bUnit）。
- `DGPM_SPM.Integration.Tests`：真實 DB／端到端煙霧測試（無連線字串時 Skip，不使預設 `dotnet test` 全紅）。

依賴方向如下：

```text
DGPM_SPM.Api ──► DGPM_SPM.Core
DGPM_SPM.Api ──► DGPM_SPM.Infrastructure
DGPM_SPM.Infrastructure ──► DGPM_SPM.Core
DGPM_SPM.Core ──► 無 ProjectReference
DGPM_SPM.Web ──►（HTTP）DGPM_SPM.Api
```

### 三條鐵律

1. `Core` 不得引用 `Infrastructure`；資料存取介面定義於 `Core`，實作放在 `Infrastructure`。
2. `Core` 不得引用 ASP.NET Core；`HttpContext` 等 HTTP 細節只能存在於 `Api`。
3. Domain Entity 與屬性使用 PascalCase，DB 的 SCREAMING_SNAKE_CASE 欄位由 `Infrastructure/Persistence/DapperTypeMapConfig.cs` 集中對應。

`tests/Architecture.Tests/LayerDependencyTests.cs` 持續守護六項分層規則，`EntityNamingTests.cs` 另守護 Entity 命名及 namespace。不得刪除、放寬、加 `[Skip]` 或繞過這些測試。

### 測試專案目錄（現況）

```text
tests/
├── Core.Tests/            DGPM_SPM.Core.Tests — Core 單元測試
├── Api.Tests/             DGPM_SPM.Api.Tests — Controller 單元測試
├── Architecture.Tests/    DGPM_SPM.Architecture.Tests — 分層／Entity 命名守護
├── Web.Tests/             DGPM_SPM.Web.Tests — Blazor 元件與導覽 helper（bUnit）
└── Integration.Tests/     DGPM_SPM.Integration.Tests — 真實 DB／E2E 煙霧
                           （無 ConnectionStrings__DefaultConnection 時需 DB 案例 Skip；
                            啟用方式見 tests/Integration.Tests/README.md）
```

### 部署到 IIS（YOUR_SERVER_HOST）

1. **主機前置**：安裝 [.NET 10 Hosting Bundle](https://dotnet.microsoft.com/download/dotnet/10.0)，安裝後重啟 IIS（或執行 `net stop was /y` 再 `net start w3svc`）。
2. **複製產物**：將本機 `d:\07-DGPM\publish\DGPM_SPM\api\`、`d:\07-DGPM\publish\DGPM_SPM\web\` 分別複製到該主機上已規劃的實體目錄（路徑見上表「待填」；首次部署可先建立目錄再貼上）。
3. **建立應用程式 logs 資料夾**（部署時必做）：
   - 於站台部署根目錄**旁邊**建立 `logs`（例：`C:\inetpub\logs`，與 `DGPM_SPM`、`PGM` 同層）。若不存在則建立。
   - **授權（必做）**：以**系統管理員**執行 [`docs/grant-inetpub-logs.bat`](grant-inetpub-logs.bat)（`icacls` 授與 `IIS_IUSRS`＋`Users` 修改權）。未授權時 NLog **無法**寫出 `DGPM_SPM_*`／`PGM_*`（目錄裡只會看到 IIS 的 `LogFiles`／`FailedReqLogFiles`／`wmsvc`）。授權後請重啟（回收）相關 App Pool。
   - **排錯**：`nlog.config` 的 `internalLogFile` 寫在同目錄 `nlog-internal-{應用}.log`；若主 log 仍不出現，先看 internal log 的權限／路徑錯誤。
   - NLog 檔名對照（`nlog.config` 寫入 `C:/inetpub/logs/`；`throwConfigExceptions=true`）：

     | 應用 | 檔名 |
     |---|---|
     | DGPM_SPM Api | `DGPM_SPM_api_yyyy-MM-dd.log` |
     | DGPM_SPM Web | `DGPM_SPM_web_yyyy-MM-dd.log` |
     | PGM Api | `PGM_api_yyyy-MM-dd.log` |
     | PGM Web | `PGM_web_yyyy-MM-dd.log` |

   - 發布後請確認站台目錄內的 `nlog.config` 與來源一致（`fileName` 指向 `C:/inetpub/logs/...`）；若仍是舊路徑請**重新 publish** 並覆蓋部署。
   - 此為**應用程式 log**；`C:\inetpub\logs\LogFiles` 仍是 IIS 系統存取紀錄，勿混淆。ANCM stdout（若有啟用）可能在站台實體目錄下的 `logs\stdout_*.log`，與上述 NLog 路徑不同。
4. **應用程式集區**：為 Api、Web 各建一個（或共用，視維運慣例）應用程式集區；**.NET CLR 版本選「無受控程式碼」**。
5. **站台／應用程式**：
   - 建立（或使用既有）IIS 站台，實體路徑指向上述目錄。
   - **綁定埠**（目前文件可確認的正式環境設定）：
     - Api：`9527`（HTTP）
     - Web：`8964`（HTTP）
6. **環境變數（Api 與 Web 分開設定）**：

> **重要架構**：`DGPM_SPM.Web` **不直連資料庫**；它只透過 HTTP 呼叫 `DGPM_SPM.Api`（`SpmApi:BaseUrl`）。真正讀寫 SQL 的是 **Api**。開發環境可用 Api 的 User Secrets；正式環境以 `Api/web.config`、`Web/web.config` 的環境變數為準（會進入 `publish`）。若未提供 Jwt／連線字串／`SpmApi__BaseUrl`，Api 無法啟動或 Web 無法呼叫 Api，Web 端會顯示「無法連線至伺服器」或「系統處理發生錯誤」。

**Api 站台／應用程式集區**（缺一不可）：

```text
ASPNETCORE_ENVIRONMENT=Production
ConnectionStrings__DefaultConnection=<SQL_SERVER_CONNECTION_STRING>
JwtSettings__SecretKey=<AT_LEAST_32_CHARACTERS_SECRET>
```

正式環境變數以專案來源 `Api/web.config`、`Web/web.config` 為準（`dotnet publish` 會一併輸出至 `d:\07-DGPM\publish\DGPM_SPM\api`、`...\web`）。目前已含 `ASPNETCORE_ENVIRONMENT=Production`、Jwt、連線字串、`SpmApi__BaseUrl`、`Auth__PgmBaseUrl`／`Auth__PgmWebBaseUrl` 等部署值；若環境變更請直接改來源 `web.config` 後重新 publish，避免 Server 手改檔與下次發布互相覆蓋。亦可改寫在 IIS 應用程式集區環境變數（會覆寫同名設定）。

若使用 Windows 驗證（`Trusted_Connection=True`／`Integrated Security=True`），請確認 **Api 應用程式集區識別身分** 對該資料庫有權限。

**Web**：本機 Debug（`ASPNETCORE_ENVIRONMENT=Development`）的 `SpmApi:BaseUrl`／`Auth:PgmWebBaseUrl` 以 `appsettings.json`＋`appsettings.Development.json` 連本機（Api `https://localhost:7221`、PGM Web `https://localhost:7230`）；正式以 `appsettings.Production.json` 與 `Web/web.config` 的 `SpmApi__BaseUrl`（`http://localhost:9527`）為準。若未來改走 HTTPS，請同步修改 `Web/web.config` 後重新 publish。

> `SpmApi:BaseUrl` 必須是 **Web 程序實際可連線到的 Api 根位址**（含協定與埠；若 Api 掛在虛擬目錄／路徑前綴，一併寫入）。**不要**在 Web 站台設定 `ConnectionStrings__DefaultConnection`（無效且易誤解）。`Api/web.config` 另含 WebDAV 停用（`<remove name="WebDAVModule" />` 等），發布時請一併覆蓋，以免 PUT 編輯再被 IIS 攔截。

7. **啟動驗證**：在 IIS 管理員啟動站台與應用程式集區後：
   - 瀏覽器開啟 Web：`http://localhost:8964`
   - Health／Swagger 對 Api：`http://localhost:9527/api/health`

IIS 承載時通常由 ANCM 轉發，**不必**再手動 `dotnet DGPM_SPM.*.dll`，也**不必**在正式環境設定開發用的 `ASPNETCORE_URLS=…:5171`；對外埠以 IIS 綁定為準。

## 設定

### 連線字串

Repository 使用設定鍵 `ConnectionStrings:DefaultConnection`（僅 **Api**／Infrastructure）。不得把真實連線字串提交至 `appsettings.json`。`Web` 無此設定、也不應設定。

開發環境請使用 User Secrets（掛在 **Api** 專案；僅 `ASPNETCORE_ENVIRONMENT=Development` 時載入）：

```powershell
dotnet user-secrets set "ConnectionStrings:DefaultConnection" "<SQL_SERVER_CONNECTION_STRING>" --project Api\DGPM_SPM.Api.csproj
```

部署環境（Production／IIS）**必須**另外提供，例如：

```text
ConnectionStrings__DefaultConnection=<SQL_SERVER_CONNECTION_STRING>
```

Api 啟動時若缺少此鍵（或空白），會直接 throw 並拒絕啟動，避免「站台看起來起來了但一登入就 500」。請查 `C:\inetpub\logs\DGPM_SPM_api_yyyy-MM-dd.log`（NLog）、站台實體目錄下的 `logs\stdout_*.log`（ANCM stdout，若有），或 Windows 事件檢視器。

### 疑難排解：發布後 Web「像連不到 DB」

依序確認：

1. **Api 是否在跑**：瀏覽 `http://localhost:9527/api/health`（或實際綁定）。若站台起不來，先看 Api 的 stdout／事件紀錄是否為缺 `JwtSettings:SecretKey` 或 `ConnectionStrings:DefaultConnection`。
2. **Api → SQL**：確認 health 回傳的 `database.connected=true`，並比對 `database.server`／`database.name` 是否與本機 Debug（User Secrets）相同。在 Api 主機用與正式連線字串相同的帳密／驗證模式測 SQL（SSMS／`sqlcmd`）。注意 `TrustServerCertificate`／`Encrypt`、防火牆、以及 Windows 驗證時的應用程式集區身分（需有 **UPDATE／INSERT**，不可僅 SELECT）。
3. **Web → Api**：確認 Web 實際使用的 `SpmApi:BaseUrl`（`web.config` 環境變數優先於 `appsettings*.json`）可從 **Web 程序所在主機** 連到 Api（不是瀏覽器本機的 localhost）。
4. Web 友善訊息對照：`無法連線至伺服器` ≈ 呼叫不到 Api；`系統處理發生錯誤`／`資料庫更新失敗` ≈ 已打到 Api 但後端例外或寫入失敗 → 看 Api log（`C:\inetpub\logs\DGPM_SPM_api_yyyy-MM-dd.log`、或 IIS `logs\stdout_*.log`）。
5. **系統功能管理與左側選單**：左側選單由 `GET /api/auth/menus`（`SysFun`：`Del_YN=N`、`Is_Menu=Y`、`Is_Enabled=Y`）動態組樹。新增／改名／啟停用後，**重新整理頁面**即可生效（不必重新登入）；葉功能需有 `Url_Path` 才會顯示為可點連結。若列表有變但側欄仍舊，請核對是否連到同一資料庫，並確認該列 `Is_Menu`／`Is_Enabled`／`Parent_ID`／`Url_Path`。

### 疑難排解：Debug 可寫、發布後變更「無效」

最常見兩類：

#### A. 正式 Api 連到與 Debug 不同的資料庫

寫進正式庫，卻用 Debug 庫／另一庫在 SSMS 核對。請：

1. 正式：`curl.exe http://localhost:9527/api/health` → 記下 `database.server`／`database.name`
2. 本機 Debug 啟動 Api 後：`curl.exe http://localhost:5171/api/health` → 比對是否相同
3. 在**同一** Server／Database 執行：`SELECT Fun_ID, Fun_Name, Fun_Desc, Chg_Date FROM dbo.SysFun WHERE Fun_ID = N'ExchangeRates'`
4. 用 JWT 直接測 Update（見下方 curl）；若回 `code=100` 且列表有變，代表 API／DB 正常，問題在觀察位置（錯庫或未重新整理側欄）

#### B. IIS 攔截 PUT／DELETE（WebDAV）— 新增可、編輯不行

Blazor Server 的 Web 程式在**伺服器端**呼叫 Api（瀏覽器 DevTools Network **看不到** `PUT /api/permission/function-list/...`，只看得到 SignalR）。典型症狀：

- Debug（Kestrel）編輯正常
- 正式：**新增（POST）成功**，**編輯（PUT）／刪除（DELETE）失敗**
- UI 顯示「資料庫更新失敗」或含 **HTTP 405** 的訊息

處理：

1. 確認已部署含下列設定的 `Api/web.config`（部署目錄 `web.config` 與來源同步）：移除 `WebDAVModule`／`WebDAV` handler，且 `aspNetCore` 的 `verb="*"`。
2. 直接對 Api 測 PUT（見下方 curl）。若 curl 也 405 → 仍是 IIS／WebDAV／Request Filtering；若 curl 成功但 Web UI 失敗 → 查 Web 的 `SpmApi__BaseUrl` 與 Web stdout。
3. 看 Api／Web 的 `C:\inetpub\logs\DGPM_SPM_{api|web}_yyyy-MM-dd.log`（或 IIS `logs\stdout_*.log`）：應有 `HTTP 405` 或業務 `code`／`traceId`。

> 其他：mixed content／CORS／anti-forgery **通常不是**此架構主因（Api 呼叫在 Web 伺服器端，JWT 在 Bearer header，非 Cookie antiforgery）。

### JWT

`JwtSettings:SecretKey` 必須至少 32 個字元，缺漏或過短時 Api 會拒絕啟動。請勿在程式碼、文件、log 或版本庫中存放真實密鑰。

本方案的 `UserSecretsId` 為 `dgpm-spm-api`。開發環境設定方式：

```powershell
dotnet user-secrets set "JwtSettings:SecretKey" "<AT_LEAST_32_CHARACTERS_SECRET>" --project Api\DGPM_SPM.Api.csproj
```

部署環境可使用：

```text
JwtSettings__SecretKey=<AT_LEAST_32_CHARACTERS_SECRET>
```

`Api/appsettings.json` 目前提供非敏感設定：

- `JwtSettings:Issuer`：`DGPM_SPM.Api`
- `JwtSettings:Audience`：`DGPM_SPM.Api`
- `JwtSettings:ExpirationHours`
- `JwtSettings:AccessTokenMinutes`

## 前端共用元件開發規範

本節說明 Blazor Web（`DGPM_SPM.Web`）既有共用元件的位置、參數、套用方式與注意事項。開發新列表頁或新選單功能時請依此規範，避免重造側欄或分頁 UI。

### 系統選單共用元件（NavMenu）

#### 1. 元件位置

| 項目 | 路徑 |
|---|---|
| UI 元件 | `Web/Components/Layout/NavMenu.razor` |
| Layout 掛載 | `Web/Components/Layout/MainLayout.razor`（`<NavMenu />`） |
| 預設 Layout | `Web/Components/Routes.razor` 的 `DefaultLayout="typeof(Layout.MainLayout)"` |
| 組樹 helper | `Web/Navigation/NavMenuItems.cs`（`NavMenuItems.Build`） |
| API Client | `Web/Services/SpmApiClient.cs` → `GetMenusAsync()` |
| API 端點 | `GET /api/auth/menus`（Bearer；`AuthController`） |
| DTO | `Web/Models/MenuDto.cs` |

資料來源為 `SysFun`，後端篩選條件：`Del_YN=N`、`Is_Menu=Y`、`Is_Enabled=Y`。葉節點需有 `Url_Path`（對應 `MenuDto.FunctionUrl`）才會顯示為可點連結。

#### 2. 必要參數

`NavMenu` **沒有對外 `[Parameter]`**；由 Layout 掛載後自行運作。依賴注入：

| 依賴 | 用途 |
|---|---|
| `AuthTokenStore` | 讀取／更新登入 session（含選單快取） |
| `SpmApiClient` | 呼叫 `GetMenusAsync()` |
| `NavigationManager` | 依目前路徑展開對應群組、高亮 |

組樹規則（`NavMenuItems.Build`）：

- `ParentId` 空白 → 模組群組（標題列，無連結）
- 有 `FunctionUrl` 且 `ParentId` 對應群組 → 子項連結
- 群組下若無可見子項 → 該群組不顯示

#### 3. 套用步驟

**一般業務頁面（走 `MainLayout`）：不需手動加 `<NavMenu />`。**

新增出現在左側選單的功能：

1. 新增 Razor 頁（例如 `Web/Components/Pages/...`）。
2. 設定 `@page "/your-path"`，且路由與 `SysFun.Url_Path` 一致（建議以 `/` 開頭）。
3. 頁面預設使用 `MainLayout`（`Routes.razor`）；僅登入頁等特殊頁需 `@layout LoginLayout`。
4. 在「系統功能管理」維護 `SysFun`：設父節點、`Is_Menu=Y`、`Is_Enabled=Y`、`Url_Path`、排序等；並確認目前登入角色已授權該功能。
5. **重新整理瀏覽器頁面**即可生效（側欄每次載入會重抓 API，不必重新登入）。

#### 4. 範例程式碼

新建業務頁（側欄會自動出現，頁面本身不寫選單）：

```razor
@page "/basic/example-items"
@inject SpmApiClient ApiClient

<PageTitle>範例清單 - DGPM SPM</PageTitle>
<h1 class="page-title">範例清單</h1>
```

若需在程式碼中自行組選單樹（例如首頁模組總覽，與側欄同源）：

```csharp
var apiResult = await ApiClient.GetMenusAsync();
if (apiResult.Succeeded && apiResult.Data is not null)
{
    var modules = NavMenuItems.Build(apiResult.Data);
    // modules：上層標題 → Children 葉節點（Title / Url / FunctionId）
}
```

`SysFun` 葉功能範例欄位對照（概念）：

| SysFun | 說明 |
|---|---|
| `Fun_ID` | 功能代碼（對應 `MenuDto.FunctionId`） |
| `Fun_Name` | 顯示名稱 |
| `Parent_ID` | 上層模組；空白為群組 |
| `Url_Path` | 路由，如 `/basic/dealers` |
| `Is_Menu` / `Is_Enabled` / `Del_YN` | 須為 `Y` / `Y` / `N` 才進選單 API |

#### 5. 注意事項

- 業務頁**不要**再自行宣告 `<NavMenu />`；已由 `MainLayout` 統一掛載。
- 登出／未登入時側欄為空；API 失敗時會退回 session 內登入時快取的選單。
- 葉功能缺少 `Url_Path` 不會出現在子項；父群組無子項則整組隱藏。
- 列表有變但側欄仍舊：確認 Web 連到的 Api／資料庫與維護畫面相同，並重新整理頁面。
- 登入頁使用 `LoginLayout`，**不含**側欄。

### 分頁控制共用元件（Pager）

#### 1. 元件位置

| 項目 | 路徑 |
|---|---|
| 元件 | `Web/Components/Shared/Pager.razor` |
| 全域 using | `Web/Components/_Imports.razor` 已含 `@using DGPM_SPM.Web.Components.Shared` |
| 標準用法參考 | `Web/Components/Pages/Dealers.razor` |

已套用頁面（節錄）：Dealers、Regions、ExchangeRates、KpiIndicators、KpiImport、KpiReview、KpiChanges、KpiPermissions、ImportLogs 等。

頁面中可直接寫 `<Pager ... />`，無需額外 `@using`。

#### 2. 必要參數

| 參數 | 型別 | 預設 | 說明 |
|---|---|---|---|
| `CurrentPage` | `int` | `1` | 目前頁碼 |
| `TotalPages` | `int` | — | 總頁數（≤0 時 UI 顯示為 1） |
| `TotalRows` | `int` | — | 總筆數 |
| `FromRow` | `int` | — | 本頁起始列（顯示用） |
| `ToRow` | `int` | — | 本頁結束列（顯示用） |
| `PageSize` | `int` | `10` | 每頁筆數；`0` 表示不分頁 |
| `PageSizeChanged` | `EventCallback<int>` | — | 下拉變更時回寫（通常用 `@bind-PageSize`） |
| `Loading` | `bool` | — | `true` 時禁用按鈕／下拉 |
| `AriaLabel` | `string` | `"分頁"` | `nav` 的 `aria-label` |
| `PageSizeOptions` | `IReadOnlyList<int>` | `[5, 10, 20, 0]` | 選項；`0` 顯示為「不分頁」 |
| `OnPageChanged` | `EventCallback<int>` | — | 點第一／上／下／末頁時傳入目標頁碼 |
| `OnApplyPageSize` | `EventCallback` | — | 按「套用」後觸發（應重載第 1 頁） |

`FromRow`／`ToRow` 由父頁計算後傳入；`Pager` 不自行推算。

#### 3. 套用步驟

1. 頁面宣告 `_pageSize`、`PagedResult<T> _page`、`_loading`，以及 `_fromRow`／`_toRow` 計算屬性。
2. 實作 `LoadPageAsync(int page)`：帶 `page`、`pageSize` 呼叫列表 API，寫入 `_page`。
3. 實作 `ApplyPageSizeAsync()`：通常 `await LoadPageAsync(1)`。
4. 表格下方、且 `_page.TotalRow > 0` 時渲染 `<Pager ... />`。
5. 使用 `@bind-PageSize="_pageSize"` 綁定每頁筆數；`OnPageChanged` 指向 `LoadPageAsync`。

#### 4. 範例程式碼

可直接複製後改 API 路徑與 DTO：

```razor
@* 列表表格省略 *@
@if (_page.TotalRow > 0)
{
    <Pager CurrentPage="_page.Page"
           TotalPages="_page.TotalPages"
           TotalRows="_page.TotalRow"
           FromRow="_fromRow"
           ToRow="_toRow"
           @bind-PageSize="_pageSize"
           Loading="_loading"
           AriaLabel="範例清單分頁"
           OnPageChanged="LoadPageAsync"
           OnApplyPageSize="ApplyPageSizeAsync" />
}

@code {
    private int _pageSize = 10;
    private PagedResult<YourDto> _page = new();
    private bool _loading;

    private int _fromRow => _page.TotalRow == 0
        ? 0
        : (_page.PageSize <= 0 ? 1 : (_page.Page - 1) * _page.PageSize + 1);

    private int _toRow => _page.PageSize <= 0
        ? _page.TotalRow
        : Math.Min(_page.Page * _page.PageSize, _page.TotalRow);

    protected override async Task OnInitializedAsync()
        => await LoadPageAsync(1);

    private async Task LoadPageAsync(int page)
    {
        _loading = true;
        try
        {
            var query = $"api/your-resource?page={page}&pageSize={_pageSize}";
            var result = await ApiClient.GetAsync<PagedResult<YourDto>>(query);
            if (result.Succeeded && result.Data is not null)
            {
                _page = result.Data;
                return;
            }
            // 顯示錯誤訊息…
        }
        finally
        {
            _loading = false;
        }
    }

    private async Task ApplyPageSizeAsync()
        => await LoadPageAsync(1);
}
```

Web 端分頁結果模型（見 `Web/Models/RegionModels.cs` 等）常見欄位：`Datas`、`TotalRow`、`Page`、`PageSize`、`TotalPages`、`HasNextPage`。

#### 5. 注意事項

- 變更每頁筆數時：下拉只更新 `_pageSize`；需按「套用」才重查（`OnApplyPageSize`）。
- `PageSize = 0` 為不分頁：後端應回全部列，`TotalPages` 通常為 1；`FromRow`／`ToRow` 計算需與上例一致。
- 無資料時（`TotalRow == 0`）慣例不顯示 `Pager`。
- `Loading` 應在 API 呼叫期間為 `true`，避免重複點擊換頁。
- 搜尋／篩選後應重設為第 1 頁再呼叫 `LoadPageAsync(1)`。
- 勿另造一套分頁按鈕；統一使用 `Pager` 以維持 UI 與無障礙標籤一致。
